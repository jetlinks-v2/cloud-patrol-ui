# 巡更 H5

与 PC 共用 `cloud-patrol-ui` 仓库、巡更后端、数据库和权限。手机入口独立构建、独立登录，不加载 SaaS 桌面布局，不创建新的业务应用或服务。排班日历不再显示 H5 入口，直接访问 `/patrol-h5/`。

## 本版功能

- 巡更管理首页：参考原小程序提供可巡更点位、冷却中、今日已完成、漏检数量四项统计，以及巡更打卡、点位管理、打卡历史、漏检申报入口。四张统计卡均可点击：前三项进入本人任务并按同一状态口径筛选，支持返回全部；完成数和完成列表均按任务归属日统计，保留已经结束的当日时段。前三项沿用原后端按角色和真实时段任务计数的口径，同点位多个任务在列表合并展示、详情保留各时段。漏检卡片进入近7日漏检页；失败显示未加载，不冒充零条。
- 巡更打卡：展示“全员 / 我的”、分类与名称筛选、五列点位网格和状态图例；小于360px时采用四列。只展示当前时间窗，点位详情保留对应巡更角色与任务，避免同一点位有多个任务时随意提交。
- 点位管理：按项目、分类和名称查询及分页；新增、编辑名称、编码、位置、状态、标签和备注，编码留空由原后端自动生成或保留。所属项目使用平台已过滤的树，普通组织不可选；点位新增沿用当前选定项目，表单中不切换项目。已存在点位的分类只读展示，H5编辑不开放关联、取消或修改分类；PC独立关联操作保持原业务规则。二维码可查看及保存。巡更角色、全员巡更、点位等级和标准配置复用现有点位配置接口，不创建第二套执行资格规则。
- “我的”显示本人巡更角色；“全员”显示当前有权访问计划的点位，其他巡更角色任务可查看但不可提交。点位可巡、冷却中、已完成使用真实任务状态，无资格、停用或非班次保持不可执行。
- 检查：使用任务保存的标准快照填写选项、精确数值、文本、图片；支持参考说明、范围和例图。
- 提交：校验必填及必需图片，后台重新校验成员、资产权限、巡更角色、班次、时间、次数和冷却间隔。
- 打卡历史：默认查询本人记录。具备点位和执行记录查询权限时，可切换项目记录并按巡更人筛选；此模式复用PC执行记录查询接口及计划资产授权，不修改移动端本人接口。支持日期、分类、等级、名称筛选，分页查看实际答案、异常标红、图片及备注。提交写入现有执行记录表，PC 查询同一份记录。
- 上传：现有巡更证据附件 API，JPEG/PNG/WebP、单张最大5MB，每项一张；文件选择不能证明现场拍摄。
- 扫码：支持 PC 生成的点位 UUID 二维码。选择本地二维码图片，通过随包的 jsQR 在本机解码，不上传图片、不调用摄像头或原生扫码；只查询当前应用授权任务，过滤非当前时段、无资格、冷却中及已完成任务。一个可提交任务进入检查表，多个巡更角色任务先选择；二维码不授权、不自动提交、不解析外站链接或旧硬件 NFC 编码。

“离线作业 → 离线模式”已支持联网下载今日本人任务与检查例图、本机填写和保存照片、同步中心手动上传。数据按应用/员工/所属项目隔离，使用IndexedDB保存真实Blob，不保存登录令牌。NFC提供编码演示，真实碰卡、定位打卡和经纬度管理暂不接入。正式 APP Bridge 仍待对接。普通输入草稿只保留在页面会话；待确认提交另外保存在当前标签页的 sessionStorage，刷新后可恢复原请求号和请求体，须手动重试。切换项目/应用/用户会阻止继续提交，不把旧用户的待确认请求带给新用户。

## 开发与构建

在 SaaS runtime-ui 工作区安装依赖，本模块声明固定版本 `jsqr@1.4.0` 与 `jsencrypt@3.3.2`、`altcha@3.2.2`。独立拉取本模块最新代码后，如宿主锁文件尚未记录这些依赖，在自己的工作区执行 `pnpm install --no-frozen-lockfile` 安装并更新本地锁文件；发布宿主时再同步锁文件与模块版本指针。本地复用共享 node_modules 时不要在共享目录执行安装或清理操作；本机采用模块本地依赖目录、各共享依赖软链接及独立 jsQR/RSA 包，未修改宿主已安装依赖。

```bash
node node_modules/vite/bin/vite.js --config vite.mobile.config.ts
node node_modules/vue-tsc/bin/vue-tsc.js --noEmit -p tsconfig.mobile.json
node --test tests/*.test.mjs
node node_modules/vite/bin/vite.js build --config vite.mobile.config.ts
```

也提供 `dev:mobile`、`typecheck:mobile`、`build:mobile` scripts。生产产物 `dist-mobile/` 与 PC 模块产物分开。

本机 H5 Vite 使用 9301；9300 的**本地临时** Vite 配置将 `/patrol-h5` 代理到 9301。H5 API 走 9300，复用原有代理：巡更到本地8502，其他请求到测试网关。9301 也可直接打开 `/patrol-h5/` 登录，各来源/标签页会话独立；日常统一使用下面的9300地址。

```text
http://localhost:9300/patrol-h5/
```

无需先登录 PC。页面加载 `mobile/public/config.json`（构建后为 `/patrol-h5/config.json`）：`applicationId` 为真实巡更应用ID，`tenantDomain` 为可选的登录项目编码默认值（本机CQHT），`title` 为标题，`apiBase` 只能为同源绝对路径（默认 `/api`）。每个部署环境须调整此配置；配置读取禁用缓存。可选 URL `applicationScope` 只校验入口与配置一致，不能覆盖应用配置；旧 `projectCode` 参数不再读取 PC 会话。不接受 URL token、用户 ID 或任意 API 地址。

登录流程参考报事报修独立 H5：项目编码＋应用账号＋密码，验证码按平台配置弹出安全验证，支持图形验证码和 ALTCHA（含挑战确认）。账号原样提交，不自动追加 `@项目编码`；读取 SaaS 登录加密配置，启用 RSA 时必须成功加密再提交，不回退明文。认证请求不携带 PC 凭证、应用或业务项目头；成功后携带该 H5 token、域和应用标识核验 `/authorize/me`，通过巡更权限校验后才保存会话。取消验证、修改输入或退出登录页会取消登录，迟到响应不保存会话。需具备巡更任务或点位查询权限才能进入，任务执行资格继续由后端独立校验。会话仅存当前标签页 `sessionStorage` 的 `patrol-h5:session`，刷新恢复前重新核验授权；配置应用变化时丢弃旧会话；登录时填写的项目编码随当前标签页会话恢复。401回登录，业务403保留会话并展示权限错误；旧请求响应不能清理新账号会话。首页提供“退出”，服务器退出失败也清理本地会话。未决提交期间禁用退出。

登录后仍须手动选择所属项目：首次只加载授权项目树，统计、任务、点位、记录和漏检不查询；选定项目后再加载，清空项目后停止业务查询并清除旧结果。项目编码为 SaaS 登录域，不是业务项目；页面中的所属项目树继续使用平台已过滤结果。

## 权限

任务及历史页提供业务项目树筛选，保留组织层级，只能选择项目节点；未选或清空时停止业务查询。请求新增可选 `X-Patrol-Project`，只收窄业务范围，不替代身份/应用权限。有效员工身份、当前应用成员以及原规则定义的角色/排班执行资格、时段均由后端校验。

`PatrolHost.request(path, method, body, options?)` 的可选 `options.projectId` 为本次业务项目；宿主应转成 `X-Patrol-Project`。上传使用所执行任务的项目。`context().projectId` 保留旧宿主会话标识的兼容契约，不作为业务项目；独立登录不再传此值。第四参数是待 APP 团队接入的契约，不是已有原生能力。

`baseMenu.json` 在现有“巡更记录”菜单中增加 `mobile`（手机巡更）授权项，不增加 PC 业务菜单。部署模板 `authentication-patrol-application.yml` 对应声明该项：

| 用途 | 功能权限 |
| --- | --- |
| 点位任务、分类筛选 | `patrol-task:query`、`patrol-category:query` |
| 我的记录、图片预览 | `patrol-execution:query`、`patrol-attachment:query`（记录菜单已有） |
| 提交结果 | `patrol-execution:submit` |
| 上传图片 | `patrol-attachment:save` |

另外必须授予当前应用中的 `patrolPlan`、`patrolCategory`、`patrolAttachment`、`user` 资产范围，并具备当前应用成员身份、巡更角色指派和适用班次；已有租户边界由 SaaS 管理，巡更不强制应用绑定租户。查询权限与提交权限分开；没有手机授权的只读用户仍不能提交。

已有环境需要增量同步巡更模块的菜单、模板和应用/角色授权。仅重启后端不会更新已持久化配置。应用布局无需修改；切换应用角色目录需配套更新认证服务及巡更服务，角色查询不依赖基础服务新接口。

## 部署

将 `dist-mobile/` 内容部署到现有运行前端站点的 `/patrol-h5/` 目录，调整该目录中的 `config.json`，并继续复用站点的 `/api` 网关代理。允许公开读取平台验证码与登录接口，业务接口保留原认证与授权。静态入口仅使用配置中的同源 API，不读取 PC 保存的 `apiUrl`；独立入口无需修改 SaaS 平台源码。

需要更新巡更后端以提供以下两个只读接口，原提交与附件接口不变：

```text
POST /park/patrol/mobile/tasks/_query    { "date": "2026-11-03", "mine": true }
POST /park/patrol/mobile/history/_query  标准 QueryParamEntity
```

任务按业务时区 Asia/Shanghai 查询与所选自然日重叠的时段；记录按接收时间筛选。详情独立展示采集时间、采集网络状态和服务器接收时间；H5首次提交时取样，待确认请求重试保留原值。采集信息为客户端报告，不能用于绕过在线时段/冷却校验，也不等同于离线补传；历史缺失显示未记录。任务读取最多1000条当日任务，超限返回业务错误，不再受无关历史计划数量限制；记录分页每页最多50条。后端强制本人记录及计划资产范围，调用方 OR 条件不能扩大范围。

## 后续 APP 接入

当前 APP 尚无已确认的 Bridge。`transport.ts` 的 `PatrolHost` 只是巡更侧的接入契约：宿主在加载 H5 模块前提供 `window.patrolHost`，实现 `context()` 与 `request(path, method, body)`。

- `context()` 返回服务器会话对应的 `userId`、`projectId`、`applicationId`，可附项目名称；每次请求前重新核对身份一致性。展示管理按钮时，需提供当前应用下的真实 `permissions: { id, actions }[]`；未提供时不展示写操作。浏览器入口从已有 `/authorize/me` 响应读取，保存与执行仍由后端分别校验。
- `request()` 仅接收巡更相对路径，支持 GET/POST/PUT，负责现有认证、项目/应用头、JSON 或 FormData 上传，返回已解包的业务结果，并保留失败状态。PUT 用于已有点位的编辑，不能自动重试写入。
- 当前二维码入口只选择本地图片识别，不调用宿主原生扫码能力。
- 正式 APP 必须确认登录态传递、WebView 存储隔离、multipart 上传、登录过期和真机行为后再实现适配器。当前不把这个接口命名为平台已有原生 API。

### WebView 适配约定

- HTML 保留 `viewport-fit=cover`，页面处理 iOS 安全区；Android 宿主应把 WebView 放在系统栏以内，或提供 CSS 变量 `--patrol-app-safe-top` / `--patrol-app-safe-bottom`，单位 px。已经由原生容器留白时传0，避免重复内边距。
- 320–359px 使用四列，360px以上使用五列；点位名称允许换行，卡片不使用固定宽高比挤压长名称。
- 检查、点位、记录页面写入浏览器历史。APP 的原生返回先调用 WebView 的 `canGoBack/goBack`；提交中或结果待确认时，页面阻止退回丢失请求。宿主如果直接销毁整个 WebView，必须先与页面协商，不能靠浏览器事件阻止原生强制关闭。
- H5 首页的返回可由可选 `PatrolHost.back()` 交给原生容器关闭；没有适配器时回退浏览器历史。
- 有 VisualViewport 时检测软键盘，输入期间将提交按钮移入文档流，避免固定按钮压住输入区。旧 WebView 使用窗口 resize 回退；保留 100vh 作为不支持 100dvh 时的高度回退。
- 请求超时使用 AbortController，不依赖较新的 AbortSignal.timeout。上线使用 HTTPS。图片选择器及权限弹窗由原生 WebView 容器承接，iOS/WKWebView、Android WebView 均须真机确认；浏览器验证不能代替这一步。

本地构建和隔离的 UI 测试不能替代真实项目会话与 APP 真机验收。

二维码图片通过系统文件选择器选择，支持不超过10MB的图片，由本机 Canvas 与 jsQR 解码。取消选图不报错，无法读取、未识别到二维码或无匹配任务分别提示；不申请摄像头权限。仍复用当前项目和用户的可执行任务匹配与多巡更角色选择。

本地 `.dev/mobile-fixture.html` 为隔离的测试数据预览入口，使用测试宿主，不请求真实业务后端。支持项目树、项目任务筛选、分类/等级选项、检查表单、响应丢失重试、记录及漏检空态；不作为真实授权、附件上传、现场扫码或漏检业务验收证据。

## 移动端视觉

独立登录页和巡更首页使用浅蓝背景、白色卡片与本地 `assets/patrol-scene.svg` 插图；统计仍使用原有时段口径，首页保留四项统计跳转和四个业务入口。“可巡更点位”和“冷却中”进入同一份当前时段点位列表，分别显示可巡更、冷却和已完成状态；“今日已完成”保留完成任务筛选，包含已结束时段。点位页仅保留扫码入口、点位筛选及状态图例，不再提供页头记录、漏检明细或顶部状态筛选栏；历史和漏检由首页入口进入。图片通过 Vite 导入，支持 `/patrol-h5/` 子路径，不依赖外部图片服务。

列表筛选参考老巡更采用双列紧凑布局，历史保留分类、等级、点位名称、日期范围和有权限时的巡更人筛选；点位管理、漏检列表同步压缩控件间距。项目筛选横向排列。点位页使用白色卡片“扫一扫”入口，继续选择本地二维码图片识别，不调用摄像头。首页移除统计口径描述。

## 图片与NFC编码演示

检查例图、已上传图片和巡更记录中的图片自动显示缩略图，点击放大；读取仍经过原附件接口。点位管理以对齐字段显示所属项目、点位分类等信息，编辑既有点位时分类只读，新建时仍选择分类。

点位页提供“NFC巡更演示”：输入点位绑定的NFC编码，由移动任务查询的可选 `nfcCode` 字段匹配。它只收窄当前应用及项目有权读取的任务；未具备员工资格、角色/排班资格、有效时段或处于冷却中的任务不能执行。此入口不调用手机读卡器，真实NFC碰卡仍待APP适配；发布时需同步部署支持该字段的巡更后端。

## 离线演示步骤

1. 在 `/patrol-h5/` 登录并选择有本人任务的所属项目，从首页进入“离线模式”。
2. 联网点击“下载今日任务”，确认缓存时间和任务数量。任务标准快照及例图全部读取成功才替换缓存，下载失败不覆盖原缓存或队列。
3. 打开“离线作业”开关，可保持联网演示，也可真正断网；此工作区不发送业务查询、图片上传或打卡。保持当前页面打开，选择有效时段任务、填写检查、选择照片，再“保存到本机”。保存成功才进入“待同步”，不计入在线完成次数。同一时段有未确认记录时不重复采集。
4. 联网并关闭开关，在“同步中心”点击“同步待上传记录”。先上传照片并保存回执，再持久化最终请求并提交。超时重试沿用相同请求号、答案、采集时间及已上传附件ID；多标签页通过浏览器Web Locks避免并发同步。
5. 同步成功展示服务器记录、原离线采集时间和照片；失败保留答案和照片及具体原因。过期、权限撤销、角色/排班、次数、冷却等仍按现有后端接收时校验，不因客户端采集时间放宽。演示应在任务有效时段内联网同步。已同步任务需联网更新缓存再采集。

本版支持已打开并登录页面中的离线作业，以及联网重新进入后的本机队列恢复；未实现Service Worker页面壳缓存或断网冷启动/刷新，也不缓存登录凭据供离线登录。浏览器存储被用户清除会丢失本机未同步数据；隐私模式或空间不足时保存明确失败。切换用户/应用/项目不会读取其他身份的离线数据。
