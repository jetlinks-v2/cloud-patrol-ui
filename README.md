# Cloud Patrol UI · 巡更 PC 与 H5

手机端源码、构建、登录上下文和授权接入见 [mobile/README.md](mobile/README.md)。H5 与 PC 共用本仓库和巡更后端；以下内容主要描述 PC 宿主模块。

Vue3/TypeScript 的 JetLinks **runtime-ui 应用模块**，不是单独登录的后台。复用宿主请求、应用上下文、ConditionFilter、ProTable 和权限按钮，不注册第二个路由器或 Axios 客户端。后端在 `项目/property-management/modules/property-patrol`，由 `services/property-patrol-service` 独立启动。

## 页面与交互

所有巡更页面共用项目工具条，组织树来自基础数据已过滤的权限树，只有 project 节点可选，其他节点置灰但可展开；清空表示全部有权项目。项目选择通过 `X-Patrol-Project` 收窄列表、候选、导出和统计，切换时清空旧选择与编辑弹窗。巡更新增按钮无需预先筛选项目；新增表单内必选所属项目，默认带入列表已选项目，修改已有数据不更换归属。导入仍须先选所属项目；等级、标准、分类、标签和图片附件归属业务项目，不提供组织共享；异常预警为当前系统应用的全局配置，应用角色在当前应用内共享。历史未归属项目数据（包括旧版组织配置）由有权人员通过工具条显式归属，不自动分配第一个项目。角色人员候选使用有效员工、SaaS应用成员、人员资产及项目组织范围交集；管理员不因管理范围获得打卡资格。

- 组织配置、用户管理、空间管理、客户管理和字典配置由 `property-base-ui` 统一提供，与收费使用同一份菜单和页面。本模块不注册基础菜单、页面或 API 副本；公共菜单沿用 `charging/*` 编码及 `property-*` 权限。
- 基础管理包含点位等级、巡更标准、分类和异常预警配置；不提供标签管理菜单或维护入口，已有点位标签数据保留。等级、标准和预警的停用与逻辑删除分离，引用中的等级/标准禁止删除；底层与历史数据保留。等级提供操作前后快照的修改记录。
- 点位管理使用当前应用角色管理的数据，不独立维护角色及成员；提供逐点位的角色/等级/标准指派及月排班模板下载、导入。内部计划不设独立菜单，编辑保留指派 ID。巡更配置同页查看和修改角色及规则，无需先保存角色；统一使用“保存”一次提交角色和规则，失败整体回滚。等级及标准可同时留空（暂不生成任务），只填一项提示补齐；已有规则两项都清空表示取消后续任务规则，历史快照保留。批量配置以首个点位为编辑基准，保存覆盖选中点位。
- 执行记录区分客户端采集时间、采集网络状态与服务器接收时间；PC支持对应展示/筛选，H5详情展示，历史缺失显示未记录。采集信息不能替代服务端在线资格校验，离线补传另行实现。
- 排班日历位于巡更点管理下，为只读月/日看板，支持日期明细导出，按原系统的任务结束日期展示。
- 标准：维护数值/文本/选项/图像四类检查项，支持精确上下限、合格选项、参考说明、必填、必需图片和例图上传/替换/预览；上传未完成时不能保存。历史任务保留标准快照。
- 规则：七天时段、指定日期覆盖、周期/次数及冷却配置，不用 JSON 输入框代替规则编辑器。日期覆盖为空表示休巡，删除覆盖后恢复星期规则。
- 任务每天 00:01 由后台生成；巡更记录按稳定任务组分页，详情展示真实时段和执行记录。
- 执行记录：条件查询、整体及逐题判定、参考范围与答案快照、例图和提交图片的受控预览，不提供管理端任意修改执行事实的入口。
- 巡更统计保留点位覆盖率、点位合格率、人员巡更覆盖率；撤下额外的完成统计菜单。点位保留已有标签选择，不恢复标签维护入口。

资源选择器使用远程搜索、已选项回显、防抖和过期响应丢弃。表格加载/空态由宿主负责，动作失败保留输入。业务时间显示采用 UTC+08:00，与后端 Asia/Shanghai 一致。

**不包含小程序或 PC 模拟打卡界面。** 点位导入导出、PC二维码图片与打印、内部漏检申报审核已有；集团模板、地图、APP现场相机采集、APP内文件选择适配、离线补传、预警通知、人员评价及集团报表仍待完成。PC/H5 NFC与定位暂缓。业务契约和接口见后端 README。文本/图片及未配置合格规则的题目保持未判定，旧记录不回算；完成次数不等于合格次数。

## 目录

- `api/`：共享请求封装与明确的实体/分页/规则类型。
- `model/`：资源权限映射、编辑副本、枚举提交值、时间和状态规则。
- `composables/`：请求与页面状态编排。
- `components/`：配置编辑、标准/频次编辑、远程选择器等复用组件。
- `views/patrol/`：10 个巡更业务页面；基础页面由公共模块提供。
- `index.ts`、`baseMenu.ts/json`、`locales/lang/`：宿主模块、菜单与双语注册入口。

## 接入 runtime-ui

正式位置为 `runtime-ui/modules/cloud-patrol-ui`，推荐按宿主已有 Git 子模块管理方式接入。宿主自动发现模块入口、菜单和字典。此仓库的库构建产物**不能**直接当成完整 SaaS 前端发布目录。

挂载到宿主后，使用宿主锁文件和依赖环境。执行模块构建时需包含认证模块，确保应用入口和路由页面同时参与构建：

```bash
# 在 runtime-ui 根目录，使用其约定的 pnpm 版本。
pnpm --filter jetlinks-web-core build -- --module-name cloud-patrol-ui,property-base-ui,authentication-manager-ui
pnpm exec vue-tsc -p modules/cloud-patrol-ui/tsconfig.json --noEmit
node --test modules/cloud-patrol-ui/tests/*.test.mjs
```

菜单权限树保留“智能巡更”根节点，依次包含巡更基础管理、巡更点管理、巡更记录、巡更统计、系统管理。业务菜单定义位于 `baseMenu.json`；`baseMenu.ts` 复用公共 `property-base-ui/baseMenu` 出口生成系统管理的巡更授权别名，保留 `patrol-system`、`patrol-User` 等既有 ID，不复制基础页面或改公共模块全局父级。独立应用通过 `getMenuFilters` 展开智能巡更一层，左侧直接显示上述五个分组，系统管理排最后；项目上下文和授权编辑树不展开。公共页面的已授权节点在应用运行时映射到 `charging/*` 路由，权限仍取服务端返回的按钮和资产范围，不凭源码补授权。

所有巡更定义均为 `owner: app`、`options.appName: cloud-patrol`。业务页面继续声明 `accessSupport: support` 和原 `assetTypes`；菜单 ID、按钮及功能权限不随展示层级变化。已有环境不能仅靠代码热更新改变持久化父级：使用 `scripts/migrate-menu-root.mjs --api <认证网关地址> --backup <备份目录>` 预览，令牌通过环境变量 `PATROL_MENU_TOKEN` 提供；确认预览后增加 `--apply`。脚本只增量恢复根节点及移动五个分组，并核验其余定义未变，不调用全量初始化、不修改角色、模板或资产策略。现有用户已授权的子菜单由平台自动补齐祖先；需实测当前应用权限树。认证模板同步保留根节点，系统管理不自动补授既有角色。部署步骤见后端 `deploy/patrol/authentication-patrol-application.yml`。

图片通过巡更附件 API 复用平台文件服务，只保存业务附件 ID；每题最多一张，支持 JPEG/PNG/WebP、最大5MB，错误时保留原附件以便重试。标准/记录菜单声明 `patrolAttachment` 与 `patrol-attachment:query`，标准保存动作另含 `patrol-attachment:save`；CloudPatrol 模板同步新增附件资产 `SELECT_AND_BIND`。已存在环境须增量更新菜单、模板、订阅和应用授权，重启不会自动补齐。PC 上传不能证明现场拍摄，APP 相机/水印和真机验收仍属后续范围。

异常预警配置保留 `patrol-warnings` ID 和 `/park/patrol/warnings` 地址，声明预警查询、保存和独立删除权限；删除按钮不自动授予现有角色。已有环境增量更新该菜单和模板，停用旧 `patrol-tags` 菜单及空分组 `patrol-tag-management`；不再提供 `/park/patrol/tags` 页面。点位菜单保留标签资产范围并声明 `patrol-tag:query`，供已有标签回显和选择使用，不增加标签保存权限。此变更不修改 SaaS 布局、后端接口或已有标签数据。

必须从 SaaS 项目的巡更应用入口进入。宿主负责身份、项目、网关地址和 `X-Asset-Scope`；不要把应用 ID 当项目 ID，也不要另外加自签 token。点位操作按钮 `patrol/points:assign`、`:importRoster` 分别映射计划、排班的 save；角色数据只读。资产权限继续独立控制。月导入使用稳定人员/角色 ID，替换当前应用整月排班前要求显式确认；旧手机号模板需重新填写。

## 当前多仓工作目录下的开发

点位页提供单点/批量“巡更配置”统一入口，弹窗内先指定角色，再配置巡检规则。角色步骤回填第一点位的角色，可仅保存角色后退出，也可保存后继续配置规则；规则步骤先校验所有点位角色相同，再按每角色选择等级/标准，可返回上一步修改角色，不要求计划名、生效截止日或排班策略。保存使用同一批量事务入口，保留历史计划身份与已生成任务；列表展示有效角色，筛选或切换分类后清除勾选。

点位导入沿旧四列表头（分类id、分类名称、点位名称、所属位置），支持xls/xlsx、10MB/1000条，先展示逐行预检，再整批新增/绑定，失败全回滚。导入沿用点位保存按钮权限，不自动指派角色。点位导出按当前全部条件（含分类），覆盖全部匹配页，最多10000条；关联名称仍须对应资产读取权限。二维码使用稳定点位UUID；单点下载带名称/编码的PNG，批量使用当前筛选全部结果打印为A4一页一码（可另存PDF），最多500点位，超限明确提示。二维码不包含token，不替代移动端授权；H5通过选择本地点位二维码图片解码并匹配授权任务，不调用摄像头或原生扫码。

`tsconfig.json` 面向正式宿主目录；`tsconfig.workspace.json` 适配当前 `园区sass/项目/智能巡更/` 到 `sass平台/cloud.jetlinks/runtime-ui/` 的位置，引用**真实宿主源码**。移动目录后必须相应调整，不能用伪造声明替代宿主类型。

可以临时链接宿主 `node_modules` 做只读依赖复用；该链接已忽略，不应提交。共享链接存在时不要在巡更目录运行可能自动安装/清理依赖的包管理器命令，避免影响正在工作的宿主。可直接调用已经安装的工具：

```bash
node --test tests/*.test.mjs
node node_modules/vite/bin/vite.js build
node node_modules/vue-tsc/bin/vue-tsc.js --noEmit -p tsconfig.workspace.json
```

独立 Vite 命令只检查模块编译及产物生成，宿主依赖外置；不能据此宣称宿主完整打包、浏览器交互、真实网关和权限联调已经通过。全量类型检查会同时检查导入的宿主源码，必须区分诊断归属，但不能忽略这些错误并宣称全量通过。模块 `tsconfig.json` 将 Vue 类型解析到宿主 `node_modules/vue`，避免子模块的独立依赖副本导致模板 ref 类型身份不一致；多仓开发使用 `tsconfig.workspace.json` 中对应的宿主路径。此设置只约束类型解析，实际发布仍使用宿主构建与依赖版本。

测试约束包含菜单/页面/后端权限/模板的契约对齐、双语 key、Vue 代理编辑副本、枚举值、任务时窗及业务时区。真实接入还必须检查分页筛选、候选人员、编辑清空字段、只读角色、生成后刷新、快照详情、跨项目/应用拒绝及失败重试。

跨仓契约测试读取 `property-management/modules/property-patrol` 中的真实后端源码。支持 SaaS 聚合布局 `cloud.jetlinks/modules/property-management` 和本地 `项目/property-management`；其他布局设置 `PATROL_BACKEND_ROOT=/absolute/path/to/property-management`（指向物业仓库根目录）。不再读取旧独立巡更后端仓库。未检出后端会明确失败，不用复制接口快照或跳过断言掩盖缺失依赖。

## 点位等级规则

规则编辑沿用旧系统的分组星期、多时段与高级指定日期配置，支持只配置指定日期或与星期规则并存，指定日期覆盖当天星期规则。频率与每次最小间隔均可用分钟、小时、天录入，间隔按时段独立保存；相等起止时间表示24小时，结束早于开始表示跨天。

后端每个配置时段生成一条任务，应巡次数为完整频率周期数乘每周期次数，保留整个时段窗口；08:00–12:00、每小时一次对应一条应巡4次的任务。旧前端校验曾用向上取整，新预览与校验统一采用旧后端实际使用的向下取整。

已生成任务组和执行记录保持原快照，同一天重跑不会替换既有时段。历史规则缺少逐时段间隔时沿用原全局值；既有空日期停巡可读并保留，新建日期规则必须填写时段。新窗口保存录入单位和独立间隔，应用模板与权限不因规则编辑而变化。

## 物业共享开发分支

物业组共享分支为 `property/2.20-dev`；巡更变更提交范围使用 `物业-巡更`。提交并推送本仓库后，在 `saas-runtime-ui` 更新 `modules/cloud-patrol-ui` 的子模块提交，再在 `cloud.jetlinks` 更新 `runtime-ui`。同事按聚合仓库记录的提交递归更新，不使用 `--remote` 将全体子模块更新到不配套版本。当前仍为开发版本，部分管理操作与报表字段尚待对齐，不作为旧系统全功能验收版本。
等级、标准列表支持当前筛选跨页导出XLSX；标签仅保留后端导出。等级附规则明细表、标准附检查项目明细表；最多10000条配置/100000条明细，超限需缩小筛选。读取继续受应用上下文及资产权限约束，未接入的集团/业务项目及关联人员字段不伪造。H5扫码见mobile/README.md，NFC与定位暂缓。

等级修改记录沿原query和资产read权限显示可信操作人、时间及业务前后值。等级/标准/预警删除使用独立delete功能与资产权限，CloudPatrol模板默认不授予删除；既有环境仅增量同步对应按钮并按职责授权，不全量初始化。

## 点位分类与角色配置

点位支持多个分类。点位列表保留“取消点位”，不再提供“关联分类”按钮：取消仅移除所选分类关系并停止对应分类的计划，保留点位和历史，不等于停用物理点位。重新关联不会自动恢复旧计划。点位编辑展示当前分类，分类关系通过专门操作调整。

指定角色和配置规则按点位、分类独立保存。分类侧栏作为弹窗默认分类；多分类概览中需明确选择所有勾选点位共有的分类，避免覆盖另一分类的配置。概览展示有效角色汇总，分类视图及导出只使用当前分类的角色。前后端须配套更新，新增分类关系接口及角色概览接口需要对应后端版本。

## 应用角色数据来源

“指定巡更角色”、规则配置、筛选及引用名称统一通过巡更后端 `/park/patrol/roles/_query` 获取当前巡更应用实例的角色。应用范围来自宿主可信上下文，不能以业务项目 ID 代替 applicationId。不提供独立角色或成员编辑弹窗，角色成员在应用角色管理中维护。点位指派、记录与移动端 DTO 使用 `roleId` / `roleName`，不保留初版自建角色兼容查询。

## 公共基础模块

PC 宿主须检出并加载 `modules/property-base-ui`（分支 `2.20`）。开发白名单包含本业务模块、`property-base-ui` 和认证模块；`build` 输出独立业务包，`build:with-base` 输出包含公共模块的宿主聚合产物。基础菜单仅由公共模块初始化一次，不再初始化本业务的旧基础菜单。已有角色须授权公共 `charging/*` 菜单，旧菜单编码不会自动迁移；仅清理对应应用的旧基础菜单，勿全量重建其他系统菜单。项目章统一使用公共组织配置的 `/seal` 文件引用契约和独立 `seal` 权限。
